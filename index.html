Event-driven autoscaling on GKE

Problem

CPU-based autoscaling only reacted after CPU spiked, so new pods started while traffic was already hitting and users saw cold-start latency during surges.

What I did

  • Scaled on Pub/Sub queue depth with KEDA’s gcp-pubsub scaler instead of CPU.
  • Wrote ScaledObjects for 3 production workloads and tuned pre-warmed replicas.
  • Used Workload Identity, with no static keys.

Result

Capacity scales as soon as the backlog grows and is ready before load peaks, eliminating cold-start latency during sudden surges.

Security audit and hardening of a production GKE environment

Problem

The audit found public endpoints without a WAF, a database reachable over a public IP, and a control plane open to shared CI runners.

What I did

  • Put Cloud Armor in front with OWASP rules and geo-blocking.
  • Moved nodes to a least-privilege service account with Workload Identity.
  • Made Cloud SQL private over VPC peering, and moved CI to self-hosted runners so the control plane could be locked down.

Result

All 6 audited controls remediated. Malicious traffic is filtered at the edge, the database is reachable only inside the VPC, and only trusted networks can reach the control plane.
